# chat.py

## зачем

"chat.py" нужен, чтобы поговорить с моделью после обучения и сравнить её с исходной. сам он ничего не считает: он запускает движок "tier" в режиме "--chat", один раз грузит веса и дальше только передаёт движку вопросы токенами и принимает ответ по одному токену. так модель не грузится заново на каждый вопрос, а переключение между обученной и исходной моделью занимает мгновение.

у файла четыре способа работы:

1. диалог в терминале с памятью прошлых реплик: "python3 chat.py".
2. вопросы по очереди из командной строки, каждый с чистого листа: "python3 chat.py "вопрос 1" "вопрос 2"".
3. проход по долям процессора: "--sweep 0.5,0.6" задаёт один и тот же вопрос при разной доле работы на процессоре, без перезагрузки весов.
4. служебный режим для окна: "--serve", обмен строками "json" через стандартный ввод и вывод.

## настройка

всё, что зависит от запуска, собрано в начале файла и берётся из переменных окружения, а если их нет, из значений по умолчанию:

- "NAME": имя запуска, от него строятся имена файлов в рабочей папке.
- "TITLE": как называть обученную модель на экране.
- "MODEL": папка модели, из неё берутся "model.safetensors", "tokenizer.json" и "config.json".
- "WORK": рабочая папка, где лежат снимок обученных весов и карта слоёв.
- "TIER_BIN": путь к движку.
- "CKPT": файл обученных весов, по умолчанию "{WORK}/{NAME}_tier1.bin".
- "TIER": карта, какие тензоры обучались, по умолчанию "{WORK}/tier_assignment_{NAME}_act.txt".
- "LOG": журнал всего вывода движка, по умолчанию "{WORK}/{NAME}_infer.log".
- "QBASE": квантованная база в формате ".tq". если задана, замороженные веса движок берёт из неё.
- "CTX": длина контекста, если она не задана ключом.
- "DATA": путь к набору, на котором шло обучение. в работе не используется, оставлен как памятка.

файл обмена с движком лежит в "/tmp/{NAME}_prompt.bin".

## ключи командной строки

- "--base": говорить с исходной моделью, без обученных весов.
- "--ab": на каждый вопрос сначала отвечает обученная модель, затем исходная. удобно сравнивать.
- "--system "текст"": системная инструкция (сцена).
- "--temp 0.5": температура.
- "--max 200": сколько токенов ответа самое большее.
- "--ctx 1024": длина контекста.
- "--top-k", "--top-p", "--min-p": отбор кандидатов после температуры. по умолчанию 0, 1 и 0, то есть отбор выключен.
- "--rep 1.1": штраф за повтор последних токенов. по умолчанию 1, то есть без штрафа.
- "--seed 7": зерно случайности для повторяемого ответа. по умолчанию случайное.
- "--sweep 0.5,0.6": список долей процессора для прохода.
- "--serve": служебный режим для окна.

все прочие слова, не начинающиеся с "--" и не стоящие после ключа со значением, считаются вопросами.

## длина контекста

если контекст не задан ни ключом "--ctx", ни переменной "CTX", файл подбирает его сам в "ctx_auto". через "hwprobe" он узнаёт, сколько памяти занимает кэш ключей и значений на одну позицию для этой модели и сколько видеопамяти сейчас свободно. под кэш отводится не больше четверти свободной видеопамяти, чтобы оставить место весам, рабочим буферам и другим программам. число позиций не превышает окна модели ("max_position_embeddings" из "config.json", читается через "arch"), округляется вниз до кратного 256 и не бывает меньше 256. если узнать память не удалось, берётся 1024.

## проверка перед запуском

если выбрана обученная модель, путь к весам не задан явно и это не служебный режим, файл проверяет, что у запуска есть "{NAME}_step.txt". этот файл появляется при первом сохранении весов. без него снимок весов существует, но заполнен нулями, и модель несла бы бессмыслицу, поэтому файл сразу завершается с понятным сообщением.

## запуск движка

движок запускается одной командой:

"tier --chat model.safetensors веса карта контекст"

здесь "веса" это файл обученных весов или "-", если нужна исходная модель, "карта" это файл карты слоёв, "контекст" это длина контекста. если задана "QBASE", в конец добавляется "--qbase" и путь к файлу ".tq". рабочая папка процесса: папка самого "chat.py".

поток ошибок движка читает отдельный поток "err_reader". движок пишет ход загрузки через возврат каретки, поэтому чтение идёт по одному знаку: каждая законченная строка записывается в журнал с меткой времени, а пока модель грузится, на экране показывается одна обновляемая строка хода загрузки (в служебном режиме она уходит событием "load"). строка, начинающаяся со слова "запрос", содержит скорость ответа, её файл запоминает, чтобы показать после ответа. строки с ошибками карты ("HIP err", "hipBLAS err", "CUDA err") сразу показываются пользователю.

основной поток ждёт от движка строку "ready". если движок завершился раньше, файл находит в журнале последнюю содержательную строку этого запуска (без меток времени и строк хода загрузки) и показывает её как причину. если процесс снят сигналом, это тоже называется, а для сигнала 9 добавляется, что, скорее всего, системе не хватило памяти. после этого файл выходит с кодом 1.

## разговор с движком

обмен идёт текстовыми строками через стандартный ввод и вывод движка.

запрос на ответ. токены вопроса записываются в файл обмена как 32 битные целые, затем движку уходит строка:

"файл число_токенов max temp top_k top_p min_p повтор окно зерно присутствие частота"

поля идут через пробел в этом порядке.

в ответ движок присылает по строке на каждый новый токен (номер токена вторым словом) и в конце строку "gen_end". окно штрафа за повтор по умолчанию 256 последних токенов, штрафы за присутствие и частоту по умолчанию нулевые.

служебные команды:

- "mode trained" и "mode base": переключить обученную и исходную модель, ответ "mode_ok".
- "scale k": сила обученных весов, ответ "scale_ok". 1 означает результат обучения как есть, 0 соответствует исходной модели, больше 1 усиливает сдвиг от обучения.
- "cpu доля": доля работы на процессоре, ответ "cpu_ok". используется в проходе "--sweep".

## сборка вопроса

разметку диалога строит "tmpl.Fmt" по шаблону самой модели, тем же способом, что и при подготовке набора для обучения. поэтому модель видит вопрос в том же виде, в каком училась. история хранится текстом, парами (вопрос, ответ), и разметка строится заново на каждый вопрос: сцена, прошлые реплики, новый вопрос.

функция "prompt" следит, чтобы вопрос вместе с местом под ответ ("--max") влез в контекст. если не влезает, самые старые реплики выпадают по одной, пока не влезет.

## вывод ответа

функция "gen" принимает токены от движка, пропускает стоповые токены шаблона ("F.stop") и после каждого токена раскодирует весь ответ целиком. на экран выводится только новый кусок текста. если раскодированный текст оканчивается неполным знаком (часть байтов многобайтной буквы ещё не пришла), вывод ждёт следующего токена, чтобы на экране не появлялся знак замены. если раскодирование изменило уже показанное начало, показанная часть урезается до общего начала и вывод продолжается от него.

после ответа "gen" немного ждёт строку скорости из журнала и показывает её тусклой строкой под ответом. если задан приёмник "EMIT", куски ответа уходят в него, а не на экран: так служебный режим отдаёт ответ окну.

цвета в терминале включаются, только если вывод идёт в терминал. если доступен "readline", в диалоге работают стрелки и история ввода.

## диалог в терминале

команды в диалоге:

- "/новый": забыть разговор.
- "/исходная" и "/обученная": сменить модель, разговор сбрасывается.
- "/сила 1.5": сила обученных весов, разговор сбрасывается.
- "/инструкция текст" или "/сцена текст": задать системную инструкцию, без текста убрать её. разговор сбрасывается.
- "/temp 0.7": температура.
- "/выход", "/exit", "/q": выйти. так же работают "ctrl+d" и "ctrl+c".

разговор сбрасывается при смене модели, силы и сцены, потому что прошлые ответы дала уже другая модель или в другой обстановке.

## служебный режим для окна

с ключом "--serve" файл ничего не печатает для человека, а пишет по одной строке "json" на событие:

- "{"load": "..."}": ход загрузки.
- "{"ready": true, "имя": "..."}": модель загружена.
- "{"tok": "кусок"}": очередной кусок ответа.
- "{"end": true, "имя", "токенов", "сек", "скорость"}": ответ закончен. такая строка приходит ровно одна на каждую строку запроса, даже на пустую.
- "{"ошибка": "..."}": ошибка движка или его завершение при загрузке.

на вход идёт по одной строке "json" на запрос. все поля необязательны:

- "q": вопрос. без него файл только применяет настройки и отвечает "end".
- "new": забыть разговор.
- "base": исходная ли модель.
- "temp" от 0 до 2, "max" от 1 до 2048.
- "сила" от 0 до 3.
- "top_k" от 0 до 1000, "top_p" от 0.01 до 1, "min_p" от 0 до 1, "повтор" от 1 до 2, "окно" от 1 до 4096, "зерно" от "-1", "присутствие" и "частота" от 0 до 2.
- "сцена": системная инструкция.
- "думать": включить размышления модели, если шаблон их поддерживает (по умолчанию выключены, модель сразу отвечает).
- "история": список пар (вопрос, ответ). окно присылает разговор своей вкладки, поэтому у каждой вкладки своя память.

значения вне пределов приводятся к ближайшей границе, неверные значения пропускаются. смена модели, силы, сцены или размышлений сбрасывает историю.

## с чем взаимодействует

- движок "tier": вся работа с весами и выборка токенов.
- "tmpl.py": разметка диалога по шаблону модели и стоповые токены.
- "hwprobe.py" и "arch.py": свободная видеопамять, размеры модели и окно контекста для подбора длины контекста.
- библиотека "tokenizers": перевод текста в токены и обратно по "tokenizer.json" модели.
- рабочая папка запуска: обученные веса, карта слоёв, "{NAME}_step.txt" и журнал.
- окно программы: в служебном режиме.

в конце работы файл закрывает ввод движка, останавливает его и пишет в журнал строку о выходе.
