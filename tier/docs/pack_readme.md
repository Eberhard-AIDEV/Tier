# pack.sh

раскладывает файлы программы по местам в системе и собирает пакет для debian и ubuntu. это единая точка, через которую проходят все способы установки: пакет для arch, пакет deb и установка в домашнюю папку без пакетного менеджера. благодаря этому набор файлов, их права, запускалка и ярлык везде одинаковые, и при добавлении нового файла в программу достаточно поправить одно место.

## как вызывать

у скрипта три команды, первое слово выбирает действие:

"bash pack.sh stage <корень> <приставка>"
раскладывает файлы. корень это каталог, который считается корнем системы (для сборки пакета это временная папка пакета). если корень пустой, файлы ложатся прямо в систему. приставка это место установки внутри корня, по умолчанию "/usr". для установки в домашнюю папку приставка "$HOME/.local".

"bash pack.sh deb"
собирает пакет "tierlm_<версия>_all.deb" рядом со скриптом и печатает его полный путь последней строкой. этот путь забирает "install.sh" и передаёт в apt.

"bash pack.sh ver"
печатает версию программы. её берёт PKGBUILD для поля pkgver.

при любом другом слове скрипт печатает подсказку по использованию и выходит с ошибкой. скрипт работает с "set -e", поэтому первая неудачная команда (например отсутствующий файл) прерывает всю раскладку, и наполовину собранный пакет не получится.

## откуда берутся данные

папка с исходниками определяется по месту самого скрипта, поэтому его можно звать из любого каталога. версия читается из строки "VERSION = '...'" в "tierlm.py", так что номер версии хранится в одном месте и пакеты всегда получают тот же номер, что показывает программа.

## раскладка (stage)

внутри приставки создаются четыре каталога:

"lib/tierlm" для всех файлов программы
"bin" для запускалки
"share/applications" для ярлыка в меню
"share/icons/hicolor/scalable/apps" для значка

в "lib/tierlm" копируются:

обычные файлы с правами 644: главная программа "tierlm.py", окно "ui.py" и "ui.qml", переводы и словарь ("en.txt", "glossary.tsv"), список известных моделей хаба "hub_known.json", исходники движка ("tier.cpp", "gpu_compat.h", "tier_wmma.h", "quant.h", "quant_tables.h"), питоновские модули (квантование, проверка квантования, подготовка данных, повтор, разговор, архитектуры, шаблоны, хаб, опрос железа, голос), образец повтора "replay.jsonl", логотип и README. туда же идут примеры данных "example_axioms.jsonl" и "example_axioms_q.txt".

исполняемые скрипты с правами 755: "auto.sh", "train.sh", "build.sh", "check.sh", "fetch_model.sh", "pydeps.sh".

целиком копируются папки "stub", "stub_cuda" (заглушки для сборки движка под amd и под nvidia) и "fonts".

исходники движка ставятся вместе с программой не случайно: движок собирается под конкретную карту при первом запуске уже на машине пользователя, поэтому в пакете лежит код, а не готовый бинарь. по этой же причине пакет не зависит от архитектуры процессора и помечен как "all".

логотип дополнительно кладётся как значок "tierlm.svg" в тему hicolor, чтобы его находили меню и панели рабочего стола.

переменные корня, приставки и папки программы объявляются как local одной строкой, а значения получают отдельными присваиваниями. так сделано потому, что в bash доводы команды local раскрываются раньше, чем выполняются присваивания в той же строке, и папка программы иначе собралась бы из пустых значений.

## запускалка

в "bin/tierlm" пишется маленький скрипт на sh. он перебирает питоны по порядку: сначала системный "/usr/bin/python3", затем первый "python3" в PATH, затем питоны с явными номерами версий от 3.14 до 3.11. у каждого проверяется, что в нём есть PySide6 с QtQuick и QtSvg, и первый подходящий запускает "tierlm.py" со всеми переданными доводами.

проверка нужна потому, что окно программы рисует сам Qt, без браузера. у кого стоит pyenv или conda, первый python3 в PATH часто не видит системных привязок Qt, и окно тогда просто не открылось бы без всякого сообщения. если не подошёл ни один питон, запускалка всё равно зовёт обычный python3, чтобы пользователь увидел настоящую ошибку импорта, а не тишину.

путь к "tierlm.py" вписывается в запускалку с учётом приставки, но без корня: при сборке пакета файлы лежат во временной папке, а запускаться будут уже из настоящего места в системе.

## ярлык

в "share/applications/tierlm.desktop" пишется ярлык для меню: название TierLM, короткое описание по русски, команда "tierlm", значок "tierlm", запуск без терминала, разделы Development и Science. поле StartupWMClass совпадает с классом окна программы, чтобы панель рабочего стола связывала открытое окно с этим ярлыком и значком.

## пакет deb

команда deb создаёт временную папку, раскладывает в неё программу с приставкой "/usr" и добавляет "DEBIAN/control". в нём:

имя пакета tierlm и версия из "tierlm.py"
раздел science, архитектура all
обязательные зависимости: python3, gawk, bash и пакеты PySide6 и QML, нужные окну (QtQuick, QtQml, QtSvg, QtWidgets, модули qtquick, layouts и window)
рекомендуемые: libnotify-bin для уведомлений и python3-pip для доустановки питоновских модулей
описание программы: замороженные веса держатся в озу и подаются в видеокарту послойно с опережающей подкачкой, обучаются собственные веса модели (срез строк матриц или целые матрицы выбранных слоёв), lora доступна для сравнения, план обучения считается до запуска, замороженная часть хранится в BF16 или в квантованном виде, движок собирается под amd или nvidia при первом запуске.

пакет собирается через "dpkg-deb --root-owner-group", поэтому все файлы внутри принадлежат root независимо от того, кто собирал. после сборки временная папка удаляется, а путь к готовому пакету печатается.

## с чем связан

"install.sh" выбирает способ установки по найденному пакетному менеджеру: на arch зовёт makepkg, на debian и ubuntu зовёт "pack.sh deb" и ставит результат через apt, в остальных случаях зовёт "pack.sh stage" с пустым корнем и приставкой "$HOME/.local".

"PKGBUILD" берёт версию через "pack.sh ver", а в шаге package зовёт "pack.sh stage" с корнем "$pkgdir" и приставкой "/usr".

"tierlm.py" служит источником номера версии и сам запускается через созданную здесь запускалку.

при добавлении в программу нового файла его нужно вписать в список раскладки в этом скрипте, иначе он не попадёт ни в один из пакетов.
