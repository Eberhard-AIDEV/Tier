# replay.py

помощник обучения, который не даёт модели забывать то, чему её не учат. пока модель учит данные пользователя, узкие данные тянут веса в ту сторону, где лежат и все остальные знания, и модель начинает портить ответы на обычные вопросы. файл решает это двумя способами и обслуживает несколько соседних задач:

1. подмешивание: к каждому примеру пользователя добавляются обычные вопросы из "replay.jsonl" с ответами самой исходной модели.
2. защита общих знаний: по обычному тексту находятся главные направления входа обучаемых матриц, и шаг обучения вдоль них ослабляется.
3. противоречия: обычные вопросы на те же темы, что и данные пользователя, из подмешивания убираются, потому что правка как раз должна менять ответы на них.
4. замер порчи: небольшой набор обычных вопросов откладывается отдельно, чтобы после обучения проверить, сколько модель испортила.
5. выбор слоёв правки по замеру силы градиента.

файл запускается из "auto.sh" как отдельная программа с подкомандой. сам он модель не считает: для всех проходов модели он вызывает движок (переменная "B"), а для перевода текста в токены вызывает "prepare.py".

## окружение

1. "B": путь к движку.
2. "M": файл весов модели.
3. "MODEL": папка модели с "tokenizer.json" (по умолчанию папка файла весов).
4. "X": ключи движка, которые передаются в каждый его запуск. ключи "--nsgd" и "--pos-dw" при проходах оценки отбрасываются, они нужны только для обучения.
5. "REPLAY_DIR": папка кэша. по умолчанию папка "replay" рядом с папкой модели.
6. "REPLAY_DATA": набор обычных вопросов, по умолчанию "replay.jsonl" рядом с файлом.
7. "REPLAY_THR": порог уверенности исходной модели, по умолчанию 0.3.
8. "REPLAY_SCENES", "REPLAY_PLAIN_MIN", "REPLAY_EXCLUDE", "REPLAY_HOLDOUT", "REPLAY_NEAR": настройки подмешивания, описаны ниже.
9. "WHITEN_ENERGY", "WHITEN_START": настройки защиты общих знаний.
10. "STAGE_PROG": файл хода этапа для окна программы.
11. "TIER_CPU_THREADS": число потоков процессора для numpy.

## потоки процессора

в самом начале, до первого импорта numpy, файл задаёт число потоков для библиотек счёта ("OMP_NUM_THREADS", "OPENBLAS_NUM_THREADS", "MKL_NUM_THREADS", "BLIS_NUM_THREADS"). по умолчанию это половина ядер: счёт на всех ядрах сразу быстро и сильно греет процессор, а выигрыш по времени мал, этап и так занимает десятки секунд. "TIER_CPU_THREADS" задаёт число явно и сильнее всего. если переменные уже заданы снаружи, а "TIER_CPU_THREADS" нет, они не трогаются.

## формат файлов с токенами

"read_bin" и "write_bin" читают и пишут тот же двоичный формат, что понимает движок. в начале число записей, дальше каждая запись: длина, позиция начала ответа и токены. если позиция записана отрицательной, за токенами идёт ещё ряд меток той же длины: метка на каждой позиции ответа, а минус один значит "эта позиция в потерю не идёт". запись идёт через временный файл с заменой, так что недописанный файл никогда не остаётся на месте настоящего.

"packs_of" повторяет жадную упаковку движка: примеры складываются в один шаг, пока сумма длин не превысит упаковку. так файл заранее знает, сколько проходов или шагов сделает движок. "loss_pos" считает, сколько позиций примера идут в потерю: весь ответ, если меток нет, или только позиции с меткой.

## проход исходной модели

"corpus_pass" общая часть подмешивания и защиты. он:

1. при наличии системных инструкций данных пишет копию набора, где каждому вопросу случайно, по частоте инструкции в данных, назначена одна из них. зерно постоянное, поэтому копия каждый раз одна и та же.
2. переводит набор в токены через "prepare.py" (без отложенной части, с инструкциями или без).
3. подбирает упаковку прохода через "eval_pack".
4. запускает движок один раз с "--retier", чтобы получить раскладку слоёв, и второй раз в режиме оценки "--eval" по всему набору. файла обученного среза нет, поэтому движок считает чистую исходную модель. что ещё выгрузить, задаёт вызывающий: предсказания ("--dump-pred") или входы матриц ("--dump-act").
5. читает вывод движка на ходу и пишет ход этапа в "STAGE_PROG": первая половина доли этапа это загрузка весов по строкам о загрузке в выводе движка, вторая это проходы по набору.
6. при ошибке движка печатает последние сорок строк его вывода и завершается с понятным сообщением.

"eval_pack" спрашивает у "hwprobe.py" размеры модели и свободную видеопамять в момент запуска и берёт такую упаковку, чтобы активации заняли не больше заданной доли свободной памяти (в режиме оценки нет обратного прохода и состояния оптимизатора, поэтому доля большая). если замерить не вышло, берётся упаковка 2048.

"prog" пишет в файл хода строку "доля, табуляция, подпись" через временный файл. без "STAGE_PROG" ничего не пишет.

## разметка подмешивания

"label" строит размеченный набор подмешивания и кладёт его в кэш. исходная модель проходит набор, и движок записывает для каждой позиции ответа, какой токен она поставила бы сама и с какой вероятностью. метками становятся именно эти предсказания, а не текст набора: модель учится "не сдвигайся от себя", а не "говори как этот текст". позиции, где исходная модель сама не уверена (вероятность лучшего токена ниже "REPLAY_THR"), в потерю не идут. примеры, где осталось меньше четырёх размеченных позиций, отбрасываются.

рядом с кэшем пишется файл ".json" со сводкой: сколько примеров, сколько позиций сохранено из скольких и как часто модель совпала с текстом набора. та же сводка печатается в поток ошибок.

"cache_path" строит имя кэша из хэша: путь, размер и время файла весов, порог, отпечаток движка, содержимое набора и, если есть, список системных инструкций. "engine_id" берёт отпечаток движка из файла ".src" рядом с ним, а без него размер и время самого движка. метки это то, что сказала модель через конкретный движок, поэтому другой движок требует новой разметки. пока ни одно из этих значений не поменялось, разметка не пересчитывается.

## сборка смеси

"mix" главная подкоманда обучения. она принимает файл токенов пользователя, путь выхода, коэффициент R и упаковку и делает так:

1. источники. основной источник: обычный размеченный набор. если в данных есть системные инструкции ("REPLAY_SCENES", файл со списком инструкций и числом их примеров), строится второй набор: те же обычные вопросы под этими инструкциями. иначе под инструкцией правки модель не видит ни одного обычного ответа и переписывает всё, что под ней спрошено. каждому вопросу достаётся одна инструкция по её частоте, поэтому разметка одна при любом числе инструкций. инструкции длиннее 2000 знаков пропускаются, берутся до тысячи самых частых. если инструкции есть меньше чем у пяти процентов примеров, второй набор не строится. доля второго набора равна доле примеров с инструкцией, но обычный набор остаётся не меньше "REPLAY_PLAIN_MIN" (по умолчанию половина). если второй набор построить не вышло, смесь собирается из обычного.
2. исключения. из источников убираются вопросы, тексты которых есть в "REPLAY_EXCLUDE" (противоречия с данными) и в "REPLAY_HOLDOUT" (вопросы замера порчи). оба списка склеиваются в один. вопросы замера убираются потому, что иначе обученная модель видела бы их при обучении и замер порчи показывал бы меньше, чем есть. сравнение идёт по тексту вопроса, который достаёт "qtext". если после исключения источник опустел, он выпадает, а если опустели все, остаются прежние.
3. соседи. при "REPLAY_NEAR" больше нуля к каждому примеру сначала подбираются до восьми самых похожих обычных вопросов. похожесть: доля общих токенов вопроса, причём токены, которые есть больше чем в трети всех вопросов, считаются служебными и не учитываются. в одном шаге модель видит правку и соседа, который меняться не должен, и правка не расползается на весь вид вопросов. соседи заполняют долю "REPLAY_NEAR" от нужного, остальное берётся обычным порядком. по умолчанию соседи выключены.
4. группы. к каждому примеру пользователя пристёгиваются примеры подмешивания, пока их позиций в потере не наберётся R раз по столько, сколько у самого примера, и хотя бы один. источник каждого выбирается случайно по весу, внутри источника вопросы идут по перемешанному кругу, а круг перемешивается заново, когда кончается. зерно постоянное.
5. выход. группы пишутся подряд, пример и его подмешивание лежат рядом и попадают в один шаг. если упаковка не задана (ноль или меньше), она берётся по самой длинной группе, чтобы пример шёл вместе со своим подмешиванием. в поток вывода печатаются три строки: "pack N" (упаковка), "steps M" (число шагов на эпоху) и "replay K" (сколько примеров подмешивания добавлено). "auto.sh" подставляет эту упаковку и файл смеси вместо исходных.

в коде "mix" есть ещё проверка противоречий по совпадению редких слов вопросов. она отключена (порог ноль), противоречия ищутся отдельной подкомандой "topics" до сборки смеси.

## противоречия и текст вопроса

обычный вопрос на ту же тему, что и вопрос из данных, спорит с правкой: данные меняют ответ, а подмешивание тянет к старому. такие вопросы нужно найти и убрать.

1. "qtext" достаёт из записи текст вопроса: декодирует токены до начала ответа без служебных токенов, убирает строки ролей шаблона диалога ("user", "model", "assistant" и подобные) и берёт последнюю непустую строку.
2. "qwords" превращает вопрос в набор слов: нижний регистр, "ё" как "е", каждое слово урезано до основы из пяти букв, однобуквенные слова отброшены, числа цифрами и словами (по русски и по английски до десяти) помечаются одной общей меткой числа.
3. "topics" находит тему каждого вопроса подмешивания: самое редкое его слово по всему набору подмешивания (вес слова: логарифм числа вопросов, делённого на число вопросов с этим словом). если эта тема есть среди слов вопросов пользователя, вопрос считается противоречием. метка числа в сравнении не участвует. тексты таких вопросов пишутся в файл по одному на строку, их число печатается в поток вывода. этот файл "auto.sh" передаёт дальше как "REPLAY_EXCLUDE".
4. "conflicts" находит противоречия по поведению модели. на вход идут два файла построчных потерь движка (строки "evex": номер вопроса, сумма потерь, число токенов) для исходной модели и для модели после короткого пробного обучения только на данных пользователя. для каждого вопроса считается рост потери на токен. противоречием считается рост от медианы плюс четыре медианных отклонения, но не меньше 0.5 ната на токен: такие вопросы правка ломает резко, много сильнее обычного разброса. тексты пишутся в файл, число печатается.

## замер порчи

подкоманда "retain" откладывает N обычных размеченных вопросов в файл движка для самопроверки после обучения. вопросы из "REPLAY_EXCLUDE" в этот набор не идут: правка и должна их изменить, считать их испорченными нельзя. отбор случаен с постоянным зерном. рядом пишется файл ".txt" с текстами отложенных вопросов, который "auto.sh" передаёт как "REPLAY_HOLDOUT", чтобы подмешивание их не брало. в поток вывода печатается число отложенных вопросов.

## выбор слоёв правки

"pick_layers" (подкоманда "layers") получает на вход строки "gprobe" движка: для каждой матрицы каждого слоя квадрат нормы градиента и квадрат нормы весов обучаемой части на нескольких шагах с почти нулевым шагом обучения на данных пользователя. сила слоя это корень из их отношения, то есть насколько данные тянут его веса относительно их величины. дальше:

1. для фактов ("down_proj") слои ищутся в середине сети, от 15 до 85 процентов глубины: там лежат факты, а края отвечают за разбор входа и сборку ответа.
2. для характера ("attn", матрицы "q_proj" и "o_proj" внимания) слои ищутся в первых 10 до 60 процентов глубины: манеру держат ранние слои внимания.
3. берутся три самых сильных слоя с промежутком не меньше одной двенадцатой глубины, чтобы правка не сжималась в одно место.

номера слоёв печатаются через запятую в поток вывода, сила по всем слоям в поток ошибок. если слоёв не нашлось, подкоманда завершается с ошибкой, и "auto.sh" оставляет слои по долям глубины.

## защита общих знаний

"whiten" готовит файл для ключа движка "--whiten". смысл: шаг правки G идёт мимо главных направлений, по которым ходит вход матрицы на обычном тексте. движок вычитает из G его проекцию на эти направления с весами f, где для каждого направления f равно единице минус единица, делённая на (1 плюс λ делённое на a). λ это собственное число ковариации входа в долях среднего, a задаёт силу. по главным направлениям шаг гасится почти целиком, по слабым почти не трогается.

как это устроено:

1. "mats_spec" переводит запись матриц ("down_proj:16,24,32", "attn:0,1,2", "q_proj+o_proj:3") в то, что выгружать движку: вход "down", вход внимания "qkv", вход "o" с номерами слоёв.
2. исходная модель проходит обычный набор с "--dump-act", и движок пишет входы нужных матриц в файлы в половинной точности bf16. эта часть занимает восемьдесят процентов хода этапа.
3. для каждой матрицы "top_dirs" находит главные направления подпространственной итерацией: случайный блок векторов несколько раз умножается на ковариацию и ортогонализуется, а сама ковариация не строится. входы читаются кусками и переводятся в одинарную точность по ходу, полная копия в памяти не держится. собственные числа нормируются на среднюю дисперсию входа.
4. направлений ищется сначала немного ("WHITEN_START", по умолчанию 64). если их доля дисперсии не набирает "WHITEN_ENERGY" (по умолчанию 0.9), число растёт вчетверо, но не больше доли "frac" от размера входа. на обычном тексте почти всю дисперсию несут несколько направлений, поэтому сразу искать все дорого и бесполезно. затем берётся столько направлений, сколько нужно для "WHITEN_ENERGY", но не меньше восьми и не больше найденного: дальние направления это шум, а не смысл.
5. по каждой матрице печатается, сколько позиций и направлений и насколько ослаблен шаг по первому и последнему направлению.

файл защиты двоичный: число матриц, затем для каждой имя, размер входа, число направлений, ряд f и направления подряд. имя файла это хэш весов, матриц, параметров, отпечатка движка и набора, он лежит в папке кэша и повторно не считается. путь печатается в поток вывода. параметры a и доля задаются аргументами, по умолчанию 0.3 и 0.1.

## подкоманды

1. "label": построить обычную разметку, напечатать путь кэша.
2. "pool": то же, путь к размеченному набору подмешивания.
3. "mix ТОКЕНЫ.bin ВЫХОД.bin R УПАКОВКА": собрать смесь, напечатать "pack", "steps", "replay".
4. "topics ДАННЫЕ.bin ВЫХОД": противоречия по теме вопроса, напечатать их число.
5. "conflicts ДО.txt ПОСЛЕ.txt ВЫХОД": противоречия по росту потери, напечатать их число.
6. "retain ВЫХОД.bin N": отложить вопросы замера порчи, напечатать их число.
7. "layers ВИД ЧИСЛО_СЛОЁВ": строки "gprobe" на входе, номера слоёв на выходе.
8. "whiten MATS [a] [доля]": построить файл защиты общих знаний, напечатать путь.

все сообщения для человека идут в поток ошибок, в поток вывода только результат, который читает "auto.sh". при неверном вызове печатается формат вызова.

## связи с другими файлами

1. "auto.sh" вызывает подкоманды в таком порядке: "topics", затем "retain", затем "mix", при замере слоёв "layers", при защите общих знаний "whiten". если подмешивание или защита не удались, обучение идёт без них.
2. "prepare.py" переводит набор вопросов в токены.
3. движок "tier.cpp" делает все проходы модели: разметку, выгрузку входов матриц, построчные потери, замер градиента.
4. "hwprobe.py" даёт размеры модели и свободную видеопамять для выбора упаковки.
5. "tierlm.py" считает число шагов эпохи с подмешиванием тем же порядком, что и "mix".
6. "replay.jsonl" набор обычных вопросов с ответами, который идёт в разметку и защиту.
